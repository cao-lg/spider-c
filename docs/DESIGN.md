# 教学设计说明

> 面向教师、教研与课程评审。学生端不需要读这一页;页面版见站点 `/design/`(可直接打印成备课稿/听课表)。

## 1. 这门课原来的问题

v1 是一个"练习驱动"的代码训练站:13 节课、每课一个自动判分的代码实操、5 套单元卷、
10 套综合测试、学习报告有雷达图和趋势线。技术完成度不低,但从教学设计看有三个结构性缺口:

| 缺口 | 具体表现 | 后果 |
| --- | --- | --- |
| 只有"做得对",没有"讲得清" | 全站没有一道概念题(题型代码写好但从未接入页面) | 学生能跑通代码却说不清 403 与 404 的区别;教师无法区分"会抄"和"懂了" |
| 只判对错,不判成因 | 答错只显示"未通过"+ 一段通用提示 | 学生反复试错;同类错误在不同学生身上重复出现,却没人知道是哪种误解 |
| 评价不指向目标 | 课程目标写的是"理解…""掌握…",不可观测 | 无法回答"这节课到底达没达成",也就无法据此调整教学 |

## 2. 改造后的结构:三类评价 + 一条错题链

```
每课:驱动性问题 → 概念讲解 → 概念检查点(2–3 题,即时诊断) → 代码实操(自动判分)
                                                                    ↓ 答错
单元:概念卷(8 题) + 实操卷(5 题) 分开记分          错题本(按误区标签聚合 + 就地重练)
                                                                    ↓
综合:10 套同构靶站综合测试 + 学习中心(掌握度雷达 / 趋势 / 概念正确率)
```

**为什么分开记分**:如果用代码通过率代表全部掌握度,概念漏洞会被"照着提示也能跑通"掩盖。
学习中心因此单列「概念题正确率」,与实战得分并列展示。

## 3. 目标怎么写

每条目标包含四个字段,缺一不可:

| 字段 | 要求 | 反例 |
| --- | --- | --- |
| `statement` | 可观察的行为动词 | ~~理解 HTTP 状态码~~ → **能根据状态码判断问题出在哪一侧** |
| `bloom` | 记忆/理解/应用/分析 | 全部标"理解"说明课程停在低阶 |
| `evidence` | 学生做出什么我才算他达成 | "能正确回答 5 个状态码场景的归因" |
| `id` | 与概念题 `objectiveId` 对齐 | — |

当前 13 课共 44 条目标,其中 35 条(80%)落在应用/分析层。这个比例是刻意保持的:
编程课若目标全在记忆层,学生会"背得出但写不出"。

## 4. 诊断性反馈:本课程最核心的资产

概念题的每个**错误选项**都写了诊断文本,说明"这个错法为什么有人会这么想"。举例:

> **Q**:脚本对某商品页返回 403,浏览器却能正常打开。最可能的原因是?
> - A. 这个页面已经不存在了 → *"不存在"对应 404。403 是 Forbidden:资源存在,但你被拒绝访问。*
> - B. 服务器识别出请求不是普通浏览器,主动拒绝 ← **正确**
> - C. 你的网络断了 → *网络断掉通常表现为连接超时,拿不到任何 HTTP 状态码。*
> - D. 服务器内部代码报错 → *那是 5xx,与你的请求特征无关。*

这样学生拿到的不是"答案是 B",而是"我原来把 403 和 404 混在一起了"。
错误选项全空的题会被构建拦下(`optionFeedback` 逐项校验)。

配合 `misconception` 标签(如 `status-code-confusion`、`range-off-by-one`、`public-equals-free`),
错题本可以按**认知误区**而不是按题目聚合。当同一标签下堆了 3 题以上,说明是概念裂缝而非粗心,
页面会直接提示"回到那一节重读,而不是继续刷题"。

当前登记 28 个误区标签,覆盖:环境与编码(3)、请求与会话(5)、解析(4)、
流程与结构(6)、反爬与动态渲染(5)、合规(2)、工程化(3)。

## 5. 课堂时间轴(教师视角)

每张设计卡给出 4–6 个环节,含"教师做什么 / 学生做什么",合计分钟数**必须等于课时时长**
(构建期校验)。设计取向:

- **导入 ≤ 10%**:用一个矛盾现象开场(如"代码一样,为什么两个人跑出两种结果"),不铺垫背景。
- **动手 ≥ 40%**:讲解之后立刻有可执行任务,教师巡视只回答"你卡在哪一步",不给完整代码。
- **检测在收口之前**:概念检查点放在小结点前,让教师带着学生的真实错误收口。
- **留一个迁移问题**:结课时问一个"换个条件还成立吗",把知识推出本节课边界。

示例(第 01 课,20 分钟):情境导入 3′ → 概念建构 5′ → 示范操作 8′ → 即时检测 3′ → 收口 1′。

## 6. 自动化守着哪些教学约束

| 约束 | 检查 | 失败后果 |
| --- | --- | --- |
| 每个目标至少被一种评价覆盖 | `catalog.test.ts` + `check-catalog.ts` | 构建失败("教了但不评") |
| 错误选项必须有诊断 | 同上 | 构建失败 |
| 误区标签必须有中文名 | 同上 | 构建失败 |
| 目标不能用不可测动词 | `catalog.test.ts` | 测试失败 |
| 时间轴合计 = 课时 | 同上 | 测试失败 |
| 先修关系无环、不自指 | 同上 | 测试失败 |
| mdx 与 course.ts 不漂移 | `check-catalog.ts` | 构建失败 |
| 靶站路径真实存在 | `check-catalog.ts` | 构建失败 |

写这些检查不是为了"更工程",而是因为**教学一致性靠人记不住**:13 课 × 44 目标 × 30 题,
任何一处改动都可能让"目标—活动—评价"三角松动,而松动不会报错,只会悄悄降低课程质量。

## 7. 已知限制与边界

1. **前端判分不能用于正式考试**。答案与诊断随页面下发,查看源码即可获取。
   它服务的是日常形成性评价("我现在懂了吗"),不是终结性认证。
2. **概念题是抽样,不是全覆盖**。30 道题覆盖 44 个目标中的一部分(其余由代码实操覆盖),
   应视为"关键概念探针",不是知识点题库。
3. **掌握度是启发式指标**。指数滑动平均(α=0.35,首答为初值)只用于呈现趋势,
   不宜作为成绩依据;4 次满分后约 0.82,刻意不收敛到 1,避免"一次走运 = 已掌握"。
4. **无班级视图**。当前是单机自学形态;若要用于课堂教学,需要额外做教师端汇总
   (导入学生导出的 JSON 或接后端),这部分尚未实现。
5. **Pyodide 的能力边界**:浏览器内无法运行 Playwright;`requests` 受同源策略限制,
   只能访问本站靶站。第 10 课因此采用"演示 + 本地实践"的混合设计,不作为浏览器内实操。

## 8. 如果要继续迭代,优先做这三件事

1. **教师端汇总**:导入全班导出的 JSON,按误区标签出"班级共性误区"报告——这是把课程
   从"自学工具"变成"课堂工具"的关键一步。
2. **题目扩充到每目标 2 题以上**:当前部分目标是单题覆盖,重测信度不足。
3. **综合测试引入题池随机抽题**:现在 10 套固定卷,长期使用会被"记答案"污染。

单个列表页装不下全部数据，网站会用「分页」把它切成多页：电商商品、新闻列表、搜索结果、图书榜单，几乎无处不在。爬虫要做的，就是找到翻页规律，把每一页都抓回来再汇总。

> **分页是爬虫最高频的模式之一**。能不能稳定翻完所有页、不漏不重、不被封，直接决定一个采集任务的成败。这一章用两个实测过的公开站点讲清"怎么翻、怎么停、怎么稳"，再给你能在运行器里直接跑的练习。

## 一、分页的本质：找到 URL 里"变"的那一截

分页没有神秘机制。手动翻两页，对比 URL，找出**变化的部分**，把它参数化即可：

> - 变化的是 `?page=1` → `?page=2` → 参数是 `page`
> - 变化的是 `/page/1` → `/page/2` → 路径末尾是页码
> - 变化的是 `?offset=0` → `?offset=20` → 偏移量分页
> - 点按钮才变、URL 不变 → 大概率是 AJAX 或 JS 渲染（第 10 章）

最常见的写法是把页数放进变量，用循环逐个替换：

```python
base = "https://books.example.com/list"
for page in range(1, 6):          # 1 到 5 页
    url = f"{base}?page={page}"
    resp = requests.get(url, headers=headers, timeout=5)
    # ...解析这一页
```

有些站点用路径分页，规律一样，只是拼法不同：

```python
url = f"{base}/page/{page}/"
```

### 常见分页模式对比

| 模式 | URL 示例 | 参数变化 | 典型站点 |
| --- | --- | --- | --- |
| 页码分页 | `?page=1` / `?page=2` | 直接替换页码 | 大多数 CMS 列表 |
| 路径分页 | `/page/2/` / `/page/3/` | 拼接路径末尾 | Quotes to Scrape |
| 偏移分页 | `?offset=0&limit=20` | 每次加 `limit` | 部分电商接口 |
| 接口参数 | `/api/quotes?page=2` | 接口的 `page` 参数 | JS 渲染站的 JSON 接口 |
| 加载更多 | 点击才更新，URL 不变 | 发 AJAX 请求 | Scrape This Site |

## 二、真实案例 1：Quotes to Scrape 翻页

### 2.1 页面现象

`https://quotes.toscrape.com/` 是 Zyte 官方公开的爬虫练习沙盒。我实测确认：首页显示 10 条名言，底部有 `Next` 按钮，点进去 URL 变成 `/page/2/`，再点变成 `/page/3/`——典型的**路径分页**。每条名言下面还有作者链接，形如 `/author/Albert-Einstein`（这正是下一章"多级爬取"的入口）。

### 2.2 找规律的三个动作

1. 打开首页，确认每页 10 条；
2. 点 `Next`，记下 URL 从根路径变成 `/page/2/`；
3. 点最后几页，确认格式是 `/page/N/`，且到某一页后 `Next` 按钮消失。

结论：起始页可以直接是 `/page/1/`，之后 `page` 递增；终止信号是"页面里没有下一页链接"。

### 2.3 完整翻页代码（本地运行）

> 下面这段请在**本地 Python 环境**运行。浏览器运行器（Pyodide）里请求公网会被 CORS 拦截、跑不通；公网案例只作讲解与本地演示。

```python
import time
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin

BASE = "https://quotes.toscrape.com"
headers = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ..."}

session = requests.Session()
session.headers.update(headers)

url = BASE + "/page/1/"      # 起始页
all_quotes = []

while url:                    # url 变为 None 时循环结束
    resp = session.get(url, timeout=10)
    resp.raise_for_status()
    soup = BeautifulSoup(resp.text, "html.parser")

    for div in soup.select("div.quote"):
        all_quotes.append({
            "text": div.select_one("span.text").get_text(strip=True),
            "author": div.select_one("small.author").get_text(strip=True),
            "author_url": urljoin(BASE, div.select_one("a")["href"]),
        })

    # 下一页是相对链接 /page/2/，用 urljoin 拼成绝对 URL
    nxt = soup.select_one("li.next a")
    url = urljoin(url, nxt["href"]) if nxt else None
    print(f"已抓 {len(all_quotes)} 条，下一页: {url}")

    time.sleep(0.5)           # 控频：别把服务器当靶子打

print("共采集:", len(all_quotes), "条")
print("作者页示例:", all_quotes[0]["author_url"])
```

### 2.4 四个关键点

- **`while url` 比 `for page in range` 更稳**：我们不知道总页数，靠"有没有下一页"来决定停不停，而不是猜一个数字。
- **`urljoin` 处理相对 URL**：页面里的 `href` 是 `/page/2/` 这种相对路径，虽然 `BASE + href` 也能用，但 `urljoin` 能正确处理 `../`、带不带斜杠等各种形式，更通用。
- **Session 贯穿全程**：翻页属于同一站点、同一会话，用 `session.get` 复用 TCP 连接，也自动带上 Cookie（万一站点要维持登录态）。
- **`time.sleep(0.5)` 是礼貌**：真人不会一秒翻十页。控频既保护服务器，也保护你的 IP。

## 三、真实案例 2：按分类"翻页"——分页不一定是数字

不是所有分页都是 `/page/N/`。本课程自托管靶站 `SITE_BASE + "/practice/level5-dynamic/"` 顶部有一排分类按钮，点 `Python` 才加载 Python 类图书。这里的"页码"其实是**分类参数**——本质仍是分页，只是变化的是 `category`。

我已实测：点击分类会触发一个 AJAX 接口，直接返回 JSON（这一点在第 10 章用 Playwright 抓包详细演示过）。所以本地可以直接请求接口，把"点按钮"换成"改参数"：

```python
import requests

base = SITE_BASE + "/practice/level5-dynamic/api/category/"
for cat in ["python", "backend", "frontend"]:   # 把分类当参数遍历
    data = requests.get(base + cat + ".json", timeout=10).json()
    print(f"{cat}: {data['total']} 本")
```

> **思路比代码重要**：看到"按钮翻数据"别急着模拟点击。先按第 10 章的三层定位法找接口——找到后，年份就只是一个可以 `for` 循环的参数。分页的形态千变万化，但"找到变化的量并参数化"这个内核不变。

## 四、三种分页模式与终止条件对比

### 4.1 三种分页模式

| 模式 | 翻页方式 | 结束条件 | 控频策略 | 适用场景 |
| --- | --- | --- | --- | --- |
| URL 页码递增 | `?page=N` 或 `/page/N/` | 空数据 / 达到最大页 | 每页固定或随机 sleep | 页码连续、页数已知或可从空页判断 |
| 下一页链接 | 抓 `li.next a` 的 href | 无"下一页"按钮 | 每页 sleep + 随机抖动 | 页码不连续、结构规范（有 Next） |
| 接口 page 参数 | `params={"page": N}` | 接口字段 `has_next` / 空列表 | sleep + 尊重 429/Retry-After | JS 渲染站，数据来自 JSON 接口 |

### 4.2 结束条件怎么选

| 结束条件 | 判断方式 | 可靠性 | 注意 |
| --- | --- | --- | --- |
| 固定页数 | `for page in range(1, total+1)` | 中 | 页数会变，写死容易漏数据 |
| 无下一页按钮 | `soup.select_one("li.next a") is None` | 高 ⭐ | 前提是页面有规范的 Next 结构 |
| 空数据 | 解析出的条目列表为空 | 高 ⭐ | 有的站点空页也返回 200，别用状态码判断 |
| 接口元信息 | `data["has_next"] is False` | 最高 ⭐ | 优先用接口给出的信号 |

> **专业要点**：终止条件优先级——接口元信息 > 无下一页 / 空数据 > 固定页数。永远优先用站点自己给出的"还有没有下一页"的信号，而不是自己猜。

## 五、工程要点：循环、去重、URL 与会话

### 5.1 while 循环 vs for 循环

| 维度 | `for page in range(...)` | `while url:` / `while True` |
| --- | --- | --- |
| 何时用 | 页数已知且固定 | 页数未知、靠"下一页"信号终止 |
| 优点 | 简单、天然有上限，不会死循环 | 自适应，不用预先知道总页数 |
| 风险 | 页数写死，站点加页就漏数据 | 忘记更新 `url` 或忘了 `break` 会死循环 |
| 建议 | 适合靶站、固定任务 | 生产首选，但必须设最大页兜底 |

稳妥写法是给 `while` 加一个**硬上限**兜底，防止意外死循环：

```python
MAX_PAGES = 1000
page = 0
while url and page < MAX_PAGES:
    ...
    page += 1
```

### 5.2 去重：翻页重叠怎么办

有些站点第 N 页末尾和第 N+1 页开头会重叠一条，导致重复采集。用 `set` 记住已见的唯一标识：

```python
seen = set()
for item in items:
    key = item["id"]          # 用唯一标识，别用会变的字段
    if key in seen:
        continue
    seen.add(key)
    results.append(item)
```

> `set` 的 `in` 是 O(1) 哈希查找，比 `list` 的 O(n) 快得多，数据量大时差距明显。

### 5.3 相对 URL 用 urljoin，别手拼

页面里的链接多为 `/page/2/`、`../detail/5` 这种相对路径。手拼 `BASE + href` 在带 `../` 时会出错，`urljoin(current_url, href)` 才能正确处理各种相对形式。

### 5.4 全程保持 Session

翻页是同一站点的连续请求。用 `requests.Session()` 复用连接、自动带 Cookie，比每次 `requests.get` 更快，也更接近真人的连续会话。

## 七、常见坑排查表

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 死循环，程序停不下来 | `while True` 里忘了更新页码或 `url`，或漏写 `break` | 每轮必须推进状态；加 `MAX_PAGES` 硬上限兜底 |
| 最后一页数据重复 | 相邻两页有重叠条目 | 用 `set` 按唯一 ID 去重 |
| 少抓一页 / 页码对不上 | `range(1, 10)` 只到 9；或页码从 0 开始却从 1 循环 | 先确认第一页是 0 还是 1；`range(1, 11)` 才含第 10 页 |
| 翻太快被封（403/429） | 请求间隔为 0，行为比真人快几百倍 | 每页 `time.sleep` + 随机抖动；遇 429 读 `Retry-After`（第 11 章） |
| 相对 URL 拼接错误 | 手拼 `BASE + href` 遇到 `/page/2/`、`../detail` 出错 | 统一用 `urljoin(current_url, href)` |
| 空页被误判为结束 | 站点偶发返回空页但实际还有数据 | 连续两页为空再停，或结合"下一页"信号一起判断 |

## 八、小结

- **找规律**：手动翻 2-3 页，对比 URL，把变化的部分参数化（页码、年份、offset）。
- **两种真实分页**：Quotes to Scrape 是 `/page/N/` 路径分页，靠 `li.next a` 判断结束；Scrape This Site 把"年份"当分页参数，走 AJAX 接口。
- **结束条件优先级**：接口元信息 > 无下一页按钮 / 空数据 > 固定页数。
- **工程四件套**：`while` + 硬上限、`set` 去重、`urljoin` 拼相对链接、`Session` 维持会话。
- **控频**：每页 sleep + 随机抖动，遇 429 尊重 `Retry-After`——礼貌也是自我保护。

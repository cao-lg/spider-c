很多现代网站的数据根本不在 HTML 里——它在背后一个 **JSON 接口** 返回，前端再用 JS 渲染。直接抓接口，往往比解析 HTML 更干净、更稳。这一章我们就聚焦「**找到 JSON 接口 → 解析 → 落库**」这条完整链路。

> 这一章是全书少有的「**数据出生地**」章节：前面抓的是别人拼好的 HTML，这里抓的是**半成品原料**。JSON 接口给的往往是结构化的原始数据，省去了大量解析工作。

## 一、为什么现代网站爱用 JSON 接口

现在的网站大多是**前后端分离**架构：后端只负责「给数据」，前端用 JS 拿到数据后**动态渲染**出页面。这意味着：

- **你在浏览器看到的 HTML，可能是 JS 事后拼出来的**——静态抓 HTML 可能拿到一堆空壳。
- 而**给数据的那个 JSON 接口**才是源头，结构清晰、字段固定，解析起来远比解析 HTML 省心。

| 对比项 | 抓 HTML 页面 | 抓 JSON 接口 |
| --- | --- | --- |
| 数据是否结构 | 藏在标签里，需解析 | 天然是键值对/数组结构 |
| 字段是否固定 | 随页面版式变化 | 接口约定固定 |
| 解析成本 | 需 BeautifulSoup/XPath | `resp.json()` 一行搞定 |
| 稳定性 | 页面一改版就失效 | 接口一般不动 |
| 适合场景 | 无接口的旧站/纯静态页 | 现代 SPA、App、电商列表 |

> 判断口诀：**F12 里能看到 `Network → XHR/Fetch` 返回 `application/json` 的请求，优先抓接口；没有接口再回来解析 HTML。**

## 二、快速回顾 JSON 语法

JSON（JavaScript Object Notation）是一种轻量数据交换格式，几乎就是「Python 字典 + 列表」的近亲。语法要点：

- **对象**用 `{}`，是键值对（对应 Python `dict`）。
- **数组**用 `[]`，是列表（对应 Python `list`）。
- 键必须用**双引号**；字符串用双引号；数字、`true/false/null` 是字面量。
- **不允许**：注释、尾逗号、单引号键。

一个典型示例及对应 Python 结构：

```python
import json

raw = '''
{
  "total": 3,
  "items": [
    {"id": 1, "title": "Python 入门", "price": 59, "on_sale": true},
    {"id": 2, "title": "爬虫实战", "price": 69, "on_sale": false},
    {"id": 3, "title": "数据清洗", "price": null}
  ]
}
'''

data = json.loads(raw)          # JSON 字符串 -> Python 字典
print(type(data))               # <class 'dict'>
print(data["total"])            # 3
print(type(data["items"]))      # <class 'list'>
print(data["items"][0]["price"])# 59
print(data["items"][2]["price"])# None  (JSON null -> Python None)
```

| JSON 类型 | Python 类型 | 备注 |
| --- | --- | --- |
| `{...}` 对象 | `dict` | 取键 `d["k"]` |
| `[...]` 数组 | `list` | 下标 `l[0]` |
| `"str"` | `str` | |
| `123` / `1.5` | `int` / `float` | |
| `true` / `false` | `True` / `False` | 首字母大写 |
| `null` | `None` | |

## 三、找到并请求 JSON 接口

### 3.1 用浏览器找接口

1. 打开页面，按 **F12** 打开开发者工具。
2. 切到 **Network（网络）** 面板，筛选 **XHR / Fetch**。
3. 刷新页面，观察返回 `Content-Type: application/json` 的请求。
4. 点开该请求，看 **Response** 里的数据，以及 **Headers** 里的 URL 和请求头（有的接口要带 `Referer`/`Authorization`）。

### 3.2 用 requests 请求接口

```python
import requests

headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
}
api_url = "https://books.example.com/api/books?offset=0&limit=20"

resp = requests.get(api_url, headers=headers, timeout=5)
resp.raise_for_status()        # 非 2xx 直接报错,避免解析空数据
data = resp.json()             # 强烈推荐:直接解析成 dict/list
print(data["total"])
```

`resp.json()` 相当于 `json.loads(resp.text)`，但**它只对合法 JSON 生效**，如果返回的是报错文本或 HTML，会抛 `json.JSONDecodeError`。所以先 `raise_for_status()` 检查状态码，是稳妥做法。

> 接口常带分页参数（如 `?offset=0&limit=20` 或 `?page=1`），翻页方式和 HTML 分页一样——循环改变参数再请求即可。

## 五、用 `.get` 兜底，避免 KeyError

真实接口的字段不一定齐全，直接用 `d["k"]` 在字段缺失时会抛 `KeyError`，让整段脚本中断。**`.get` 是爬虫里最常用的兜底手段**：

```python
# 直接取值:字段缺失就崩
# print(item["discount"])           # KeyError

# 用 .get:缺失时返回 None,或给一个默认值
print(item.get("discount"))          # None
print(item.get("discount", 0))       # 0
print(item.get("price", 0) or 0)     # price 为 null 时也兜成 0
```

## 六、串联靶站：Level 4 JSON 接口

我们的 [Level 4 靶站](/practice/level4-json-api/) 本身就是一个返回 JSON 的接口站。打开它的 API 地址，看返回结构，再写成代码：

```python
import requests

# Level 4 靶站的分页 JSON 接口
api_url = "https://crawler-course.app.workbuddy.host/practice/level4-json-api/api/books?page=1"

resp = requests.get(api_url, timeout=5)
data = resp.json()          # 直接拿到字典,不用解析 HTML

# 遍历整页数据
for book in data.get("items", []):
    print(book.get("title"), "->", book.get("price"))
```

点击上方分页参数，把第 2、3 页也抓下来，你就完成了「**接口分页爬取**」这一常见实战动作。

## 七、用 SQLite 持久化

抓来的数据要落库才方便查询。标准库 `sqlite3` 零配置、随 Python 自带，是最轻的落地方式。

### 7.1 基本流程四步

| 步骤 | 代码 | 作用 |
| --- | --- | --- |
| 连接 | `conn = sqlite3.connect("books.db")` | 打开/创建库文件（`:memory:` 为内存库） |
| 游标 | `c = conn.cursor()` | 执行 SQL |
| 执行 | `c.execute("CREATE TABLE ...")` | 建表/增删改查 |
| 提交+关闭 | `conn.commit(); conn.close()` | 保存并释放 |

### 7.2 建表、插入、查询、提交

```python
import sqlite3

conn = sqlite3.connect("books.db")   # 换成文件名即持久化
c = conn.cursor()

c.execute("CREATE TABLE IF NOT EXISTS book (title TEXT, price INTEGER)")

# 参数化插入:用 ? 占位符,杜绝 SQL 注入(绝不要用 f-string 拼)
c.execute("INSERT INTO book VALUES (?, ?)", ("Python 入门", 59))
c.executemany("INSERT INTO book VALUES (?, ?)",
              [("爬虫实战", 69), ("数据清洗", 49)])

conn.commit()                        # 忘记 commit 数据不会落盘!

# 查询
rows = c.execute("SELECT * FROM book ORDER BY price DESC").fetchall()
for row in rows:
    print(row)

conn.close()
```

> **为什么绝不用 f-string 拼 SQL？** 用户/网页里的内容可能含 `'; DROP TABLE book;--`，直接用会把你的库「洗」掉。`?` 占位符让 `sqlite3` 帮你转义，是唯一的正确姿势。

## 九、常见坑与排查

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `json.JSONDecodeError` | `resp.json()` 解析到了非 JSON 内容 | 先 `raise_for_status()`，或打印 `resp.text[:200]` 看返回什么 |
| `KeyError` | 直接 `d["k"]` 而字段不存在 | 用 `d.get("k", 默认值)` |
| 中文乱码 | 编码设置不对 | `resp.encoding = "utf-8"`，必要时见响应头 |
| `No such table` | 忘记建表，或其表名拼错 | 检查 `CREATE TABLE` 与查询表名一致 |
| 数据没存下来 | **忘记 `commit()`** | 每次写操作后 `conn.commit()` |
| SQL 被注入 | 用 f-string 拼 SQL | 一律用 `?` 占位符参数化插入 |
| 插入报错 | `null` 写进 NOT NULL 字段 | 用 `.get(k) or 0` 等兜底，或改表结构允许 NULL |
| 结果 `None` | JSON `null` 转成了 Python `None` | 用 `or 默认值` 进一步兜底 |

## 十、小结

- **接口优先**：现代网站用 JSON 接口给数据，`resp.json()` 比解析 HTML 干净。F12 → Network → XHR/Fetch 找 `application/json`。
- **JSON ↔ Python**：`json.loads` 字符串→字典；对象/数组/`null` 分别对应 `dict`/`list`/`None`。
- **容错**：嵌套取值优先 `.get(k, 默认值)`，避免 `KeyError` 中断脚本。
- **分页**：改造 `offset`/`limit` 或 `page` 参数循环抓取。
- **落库**：`sqlite3` 零配置，流程 = `connect` → `cursor` → `execute` → `commit` → `close`；插入一律用 `?` 占位符防注入。
- **持久化**：`:memory:` 适合练手，真实数据用文件名（如 `books.db`）。

XPath（XML Path Language）原本是为在 XML 文档里定位节点而设计的，因为它能表达**层级关系、谓词过滤、轴（父子/兄弟）**，在复杂页面上比 CSS 选择器更灵活。爬虫里我们通常用 `lxml` 这个高性能解析库来执行 XPath。

> **为什么学 XPath？** BS4 的 CSS 选择器已经很好用了，但有一类定位它做不到——「按文本内容找标签」和「向上找父节点」。比如你想找「包含文字「Python」的 `<span>` 标签的**父元素**」，XPath 一句话搞定，BS4 则要多层嵌套。XPath 不是要取代 CSS，而是补上 CSS 够不着的那部分。

这一章从路径语法讲到轴，再落到一个真实站点，最后给你一张"XPath vs CSS"的对照表——学完你能根据场景在两个工具间自由切换。

## 一、XPath 路径语法：四个符号走天下

XPath 用「路径」描述你要找的节点，核心符号只有四个：

| 符号 | 含义 | 示例 |
| --- | --- | --- |
| `/` | 从根节点开始的**直接子级** | `/html/body/div` |
| `//` | 从当前节点开始**任意层级后代** | `//div`（页面所有 div） |
| `[]` | **谓词（过滤条件）** | `//li[@class='book']`（class 为 book 的 li） |
| `@` | 取**属性** | `//a/@href`（所有链接的 href） |

还有几个高频用法：

- `*` 通配任意标签：`//div/*` 取 div 的所有直接子元素
- `text()` 取文本节点：`//span/text()`
- 下标从 **1** 开始：`//li[1]` 是第一个 li，`//li[last()]` 是最后一个
- 多个条件：`//li[@class='book' and @data-id]` 同时满足

> ⚠️ **和 CSS 不同，XPath 的索引从 1 开始**！这是新手最常踩的坑——Python 列表下标从 0 开始，CSS 的 `nth-child` 也从 1 开始，但很多人会把 `li[0]` 的思维带进来。XPath 里 `//li[0]` 永远是空。

### 1.1 绝对路径 vs 相对路径

| 写法 | 起点 | 示例 | 抗改版能力 |
| --- | --- | --- | --- |
| 绝对路径 | 从根 `/` 一层层数下来 | `/html/body/div/div/span` | ❌ 极差，中间加个 div 就失效 |
| 相对路径 `//` | 全文档任意位置搜 | `//span[@class='text']` | ✅ 强，不依赖中间层级 |

**经验**：除非页面结构极端稳定，一律用 `//` 开头的相对路径，别写 `/html/body/...` 这种"悬崖式"绝对路径。

### 1.2 谓词的几种常用形态

```python
//li[1]                      # 第 1 个 li（索引从 1 开始）
//li[last()]                 # 最后一个 li
//li[last()-1]               # 倒数第 2 个
//li[position()<=3]          # 前 3 个（注意：正文里要写"小于等于"，代码里用符号没问题）
//a[@href]                   # 有 href 属性的 a
//a[@href='/tag/love']       # href 精确等于某值
//div[contains(@class,'quote')]   # class 含 quote（模糊匹配）
```

## 二、用 lxml 解析

## 三、文本提取与属性定位

- **取文本**：`//span/text()` 返回文本列表；若要「把整段文字拼成一个」，用 `element.text_content()`（lxml 元素方法）或 `' '.join(...)`。
- **取属性**：`//img/@src` 直接拿到图片地址列表，常用于批量抓图。
- **按文本过滤**：`//a[contains(text(),'详情')]` 选中文字含「详情」的链接；`contains()` 也常用于属性：`//div[contains(@class,'book')]`（class 含 book 即可，避免多值 class 精确匹配落空）。

> **text() 返回的是列表**：`doc.xpath("//span/text()")` 得到的是字符串列表，不是单个字符串。想拿第一个用 `[0]`，想拼接用 `"".join(...)`。忘了这点，后面字符串操作会莫名报错。

如果你想把一个节点里**所有后代文字**拼成一段，`text_content()` 比 `text()` 更顺手：

```python
div = doc.xpath("//div[@class='quote']")[0]
print(div.text_content().strip())   # 名言正文 + 作者 + 标签文字，拼成一段
```

再来一个练习——这次 class 属性是多值的（`book hot`），精确匹配会漏掉，你需要用 `contains`：

## 四、XPath 高级用法：轴（Axes）

轴是 XPath 真正强于 CSS 的地方。它能沿着"层级关系"往任意方向走。

### 4.1 按文本内容查找

```python
# 找到包含「Python」文字的 <span> 标签
titles = doc.xpath("//span[contains(text(), 'Python')]/text()")
```

### 4.2 向上找父节点 / 祖先

```python
# 找到所有 <span> 的父 <li> 标签
parents = doc.xpath("//span/parent::li")

# 找到某节点所有层级的 <div> 祖先
ancestors = doc.xpath("//span[@class='text']/ancestor::div")
```

### 4.3 获取兄弟节点

```python
# 找到所有 <a> 之后的第一个兄弟 <li>
siblings = doc.xpath("//a/following-sibling::li[1]")

# 之前的兄弟
prev = doc.xpath("//a/preceding-sibling::li[1]")
```

常用轴速记：

| 轴 | 含义 | 示例 |
| --- | --- | --- |
| `parent::` | 直接父节点 | `//span/parent::li` |
| `ancestor::` | 所有祖先 | `//span/ancestor::div` |
| `child::` | 直接子节点（可省略） | `//ul/child::li` ≈ `//ul/li` |
| `following-sibling::` | 之后的兄弟 | `//a/following-sibling::li` |
| `preceding-sibling::` | 之前的兄弟 | `//a/preceding-sibling::li` |
| `descendant::` | 所有后代（可省略） | `//div/descendant::span` ≈ `//div//span` |
| `self::` | 节点自身 | `//div/self::*` |

> **轴的价值**：CSS 只能"往下"选，而 XPath 的轴让你能"往回走"——这在"先按文字找到某元素，再回溯它的容器"这类场景里无可替代，也是很多人宁愿学 XPath 也不愿用 BS4 层层 `.parent` 的原因。

### 4.4 相对路径 `.//` 的坑（重要）

这是"我明明写对了却抓不到"的高频原因。当你**已经在某个元素对象上**再调用 `.xpath()` 时，表达式开头的 `.` 表示"从当前元素出发"：

```python
# 正确：在容器 div 内部找，用 .// 相对路径
for div in doc.xpath("//div[@class='quote']"):
    text = div.xpath(".//span[@class='text']/text()")   # 有前导点，从 div 内部找
    print(text)

# 错误：忘写点，变成从整篇文档根部再搜一次，会把所有名言都捞回来
wrong = doc.xpath("//span[@class='text']/text()")       # 全局，不是当前 div 内部
```

> **口诀**：在 `element.xpath()` 里用 `.//`；在 `doc.xpath()`（文档对象）里用 `//`。少了那个点，容器内提取就变成全局提取。

## 五、真实案例：用 XPath 定位 quotes.toscrape.com

用上一章的同一站点 `https://quotes.toscrape.com` 做对照——同一份 HTML，看看 XPath 怎么写。该站每条名言是 `div.quote` 容器，内含 `span.text`、`small.author`、`a.tag`（实测结构，见第 4 章）。

下面这段在**本地 Python 环境**运行（公网请求请勿放进浏览器 CodeRunner）：

```python
import requests
from lxml import html

resp = requests.get("https://quotes.toscrape.com/", timeout=10)
doc = html.fromstring(resp.text)

# 一次定位每条名言容器，再在容器内用相对路径取字段
for div in doc.xpath("//div[@class='quote']"):
    text   = div.xpath(".//span[@class='text']/text()")[0]
    author = div.xpath(".//small[@class='author']/text()")[0]
    tags   = div.xpath(".//a[@class='tag']/text()")
    print(author, "—", text[:45], "| 标签:", tags)
```

输出示例（真实内容）：

```
Albert Einstein — “The world as we have created it is a process of our ...” | 标签: ['change', 'deep-thoughts', 'thinking', 'world']
J.K. Rowling — “It is our choices, Harry, that show what we truly are, ...” | 标签: ['choices', 'abilities']
```

**对照第 4 章的 BS4 写法**：逻辑完全一样（先找 `div.quote` 容器，再取三个字段），只是把 `select`/`select_one` 换成了 `xpath`，并把 CSS 选择器换成路径表达式。两种工具殊途同归。

> **命名空间提示**：XPath 在标准 XML（如带 `xmlns` 的 SVG、某些 API 返回的 XML）里会遇到命名空间——元素名前面带前缀，直接写 `//tag` 会匹配不到，需要用 `local-name()` 或注册 namespace 映射。普通网页 HTML 没有命名空间，不用担心；只有解析 XML 时才需注意。

## 六、XPath vs CSS 选择器语法对照

两张表帮你在两个工具间切换。第一张是**语法层面的逐项对照**：

| 需求 | CSS 选择器 | XPath |
| --- | --- | --- |
| 所有 div | `div` | `//div` |
| class 为 book | `.book` | `//*[@class='book']` |
| class 含 book | `[class*='book']` | `//*[contains(@class,'book')]` |
| 第 2 个元素 | `li:nth-child(2)` | `//li[2]`（索引从 1 开始） |
| 最后一个 | `li:last-child` | `//li[last()]` |
| 取属性 | 需取出标签再 `.get()` | `//a/@href`（直接拿到值） |
| 按文本过滤 | ❌ 不支持 | `//a[contains(text(),'详情')]` ✅ |
| 直接子元素 | `ul > li` | `//ul/li` |
| 后代元素 | `ul li` | `//ul//li` |
| 父节点 | ❌ 不方便 | `//li/parent::*` ✅ |
| 下一个兄弟 | `li + li` | `//li/following-sibling::li[1]` |

第二张是**解析库层面的取舍**：

| 维度 | lxml `etree` / `html` + XPath | BeautifulSoup + CSS |
| --- | --- | --- |
| 性能 | ⚡ 快（C 实现） | 慢（Python 实现） |
| 按文本定位 | ✅ 原生支持 | ❌ 不支持 |
| 向上找父/祖先 | ✅ 轴强大 | ⚠️ 只能 `.parent` 逐层 |
| 容错性 | 中等 | ✅ 好（自动修复标签） |
| 学习曲线 | 较陡（路径语法） | 平缓（前端熟悉） |
| 典型组合 | 复杂结构、需文本定位 | 简单结构、快速开发 |

**经验法则**：

- 简单「按 class/id 取一批标签」→ CSS（`soup.select`）更直观。
- 需要「按文字内容定位」「向上找父节点」「跨层级兄弟」→ XPath 更省力。
- BeautifulSoup 本身不原生支持 XPath，要配合 `lxml` 使用。

## 七、常见 XPath 表达式速查

| 需求 | XPath 表达式 |
| --- | --- |
| 所有 `<a>` 标签的 `href` | `//a/@href` |
| 所有 `<img>` 的 `src` | `//img/@src` |
| 第一个 `<li>` | `//li[1]` |
| 最后一个 `<li>` | `//li[last()]` |
| 包含文字「详情」的 `<a>` | `//a[contains(text(),'详情')]` |
| class 含 `book` 的 `<div>` | `//div[contains(@class,'book')]` |
| `<li>` 的父节点 | `//li/parent::*` |
| `<a>` 的下一个 `<li>` 兄弟 | `//a/following-sibling::li[1]` |
| 容器内取文本（相对路径） | `.//span/text()` |

## 八、常见坑排查表

| 现象 / 报错 | 常见原因 | 排查方向 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'lxml'` | 没装 lxml | 本地 `pip install lxml`；浏览器运行器确认是否已内置 |
| `//li[0]` 抓不到任何东西 | XPath 索引从 1 开始，没有第 0 个 | 改成 `//li[1]` |
| 取文本报"列表索引越界"或类型错 | `text()` 返回列表，不是字符串 | 用 `[0]` 取第一个或 `"".join(...)` 拼接 |
| 容器内提取却抓回全页数据 | `element.xpath()` 里漏写前导点 | 把 `//` 改成 `.//` |
| 带 `xmlns` 的 XML 里怎么写都匹配不到 | 命名空间前缀导致标签名不匹配 | 用 `local-name()` 或注册 namespace 映射 |
| 精确 `@class='book'` 漏掉多值 class | 实际是 `class='book hot'` | 改用 `contains(@class,'book')` |
| 页面结构一变选择器全失效 | 写了 `/html/body/...` 绝对路径 | 改用 `//` 相对路径 |
| 中文文本匹配不到 | 页面编码读取错误 | 先修正 `resp.encoding` 再 `fromstring` |

> **调试心法**：XPath 不对时，先在浏览器控制台用 `$x("表达式")` 验证，或在 Python 里 `print(doc.xpath("//div")[0])` 逐层缩小范围。别在整篇文档上盲猜——先确认容器，再往里加条件。

## 九、小结

- XPath 四件套：`/` 子级、`//` 后代、`[]` 过滤、`@` 属性；**索引从 1 开始**。
- `lxml.html.fromstring()` + `.xpath()` 是爬虫里最快的 XPath 方案，`text()` 和 `@属性` 都返回列表。
- `contains()` 做模糊匹配；`parent::` / `ancestor::` / `following-sibling::` 等轴能取父节点和兄弟。
- 在元素对象上提取用 `.//` 相对路径，别漏前导点；XML 命名空间用 `local-name()` 处理。
- 和 CSS 不是替代关系：简单结构用 CSS，复杂定位（按文本、向上找父）用 XPath。
- 真实案例：`quotes.toscrape.com` 用 `//div[@class='quote']` 定位容器，`.//span/text()` 等相对路径取字段。
- 练手去 [Level 1 靶站](/practice/level1-books/) 用 XPath 把 24 行书名抓出来。

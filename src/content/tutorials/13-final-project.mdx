## 一、真实案例：图书采集项目端到端实测

先看一个我实测过的公开教学站点：**`books.toscrape.com`**（Zyte 官方提供的爬取沙盒，明确用于练习）。

- 列表页每页 **20 本书**，每本是一个 `article.product_pod` 卡片；
- 卡片含书名（`h3 a` 的 `title` 属性）、价格（如 `£51.77`）、评分（`p.star-rating` 的 class）；
- 详情页有书名、价格、`In stock` 库存状态、产品描述；
- 分页通过 `catalogue/page-2.html` 递增，最后一页"下一页"按钮消失。

最小骨架如下（**本地运行**，公网请求在课程运行器里不可用）：

```python
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin
BASE = "http://books.toscrape.com/catalogue/"
def parse_list(html, page_url):
    soup = BeautifulSoup(html, "html.parser")
    books = []
    for card in soup.select("article.product_pod"):
        a = card.select_one("h3 a")
        books.append({
            "title": a["title"],
            "price": card.select_one("p.price_color").get_text(strip=True),
            "rating": card.select_one("p.star-rating")["class"][1],
            "detail_url": urljoin(page_url, a["href"]),
        })
    return books
all_books = []
for page in range(1, 6):
    url = urljoin(BASE, f"page-{page}.html")
    resp = requests.get(url, timeout=10)
    resp.raise_for_status()
    batch = parse_list(resp.text, url)
    all_books.extend(batch)
    print(f"第 {page} 页: {len(batch)} 本")
print("共采集:", len(all_books), "本")
```

> **实测提醒**：价格以 `£` 开头，解析后先去掉符号再转 float。"库存"只在详情页有——要库存就得进详情页，成本翻倍，先问自己真的需要吗？

课程靶站还有两个轻量入口适合先跑通逻辑：`/practice/level1-books/` 是约 24 行的静态 HTML 表格，练 CSS 选择器；`/practice/level4-json-api/` 是分页 JSON 接口，练翻页参数与 `resp.json()`。

**专业流程**：先在靶站把解析调通，再切到沙盒站，最后才考虑真实商业站点（按第 12 章做完合规评估）。

## 二、需求分析与数据建模

项目起步最忌讳"边写边想"。先把需求写清楚：

- **约束**：守 robots.txt、控频率、出错不中断、不碰个人信息。

| 步骤 | 技能 | 章节 |

| 解析 HTML / JSON | BeautifulSoup、`resp.json()` | 第 4、9、10 章 |

**数据建模：先把字段定死**——字段名、类型、单位要在写第一行解析代码前确定：

| 字段 | 类型 | 来源 | 校验规则 |
| --- | --- | --- | --- |
| `title` | 字符串 | `article.product_pod h3 a[title]` | 非空 |

## 三、项目模块划分与架构决策

| 模块 | 职责 | 典型实现 |
| --- | --- | --- |
| 采集 Fetch | 发请求、重试、控频、守合规 | `fetch_page(url)` 返回 HTML 或 None |
| 解析 Parse | HTML / JSON 转成干净记录 | `parse_list(html)` 返回字典列表 |
| 存储 Store | 写入 CSV / SQLite / JSON | `save_csv()`、`save_sqlite()` |
| 分析 Analyze | 统计、分组、排序、校验 | `Counter`、`statistics` |
| 展示 Present | 报告、图表、控制台输出 | `print`、matplotlib |

模块之间只通过**数据契约**（记录字典的字段）通信：解析改了存储不用动，存储从 CSV 换成数据库，采集模块无感。

**决策 1：硬编码 vs 配置化**

| 写法 | 示例 | 问题 / 优点 |
| --- | --- | --- |
| 硬编码 | `for page in range(1, 51)`、`url` 散落各处 | 改页数要翻遍代码，换站点等于重写 |
| 配置化 | 顶部集中 `BASE`、`MAX_PAGE`、`HEADERS`、`SLEEP_RANGE` | 一处修改全局生效 ✅ |

把易变的东西（URL、页数、UA、延时、文件名）集中到常量区，甚至抽到 `config.py`。

**决策 2：单体脚本 vs 分层架构**

| 维度 | 单体脚本 | 分层架构 |
| --- | --- | --- |
| 代码组织 | 一个 `main()` 写到底 | `fetch` / `parse` / `store` 各自成函数 |
| 调试 | 出问题整体重跑 | 单独测 `parse`，喂一段 HTML 即可 |
| 适合场景 | 一次性抓几十条 | 长期维护、多站点复用 ✅ |

> **经验法则**：超过 100 行、或以后可能再改的爬虫，就该分层。核心是**每个模块都能单独验证**——这是排查问题的前提。

## 四、分步实现：项目结构与完整骨架

项目骨架：`crawler/` 下有 `crawler.py`（主程序）、`config.py`（配置常量，可选）、产出 `books.csv` 与 `books.db`、日志 `crawler.log`。`crawler.py` 内部分八步：检查 robots → 请求 → 解析 → 校验 → 存 CSV / SQLite → 异常与日志 → 控频重试。

完整架构模板（**本地运行**，每个函数职责单一）：

```python
"""图书榜爬虫 - 完整版模板：请求、解析、校验、存储、异常、日志、控频"""
import requests
from bs4 import BeautifulSoup
import csv, sqlite3, time, logging, random
logging.basicConfig(filename="crawler.log", level=logging.WARNING)

def fetch_page(url, headers):
    for attempt in range(3):
        try:
            resp = requests.get(url, headers=headers, timeout=5)
            resp.raise_for_status()
            return resp.text
        except requests.exceptions.RequestException as e:
            logging.warning(f"失败: {e}")
            time.sleep(random.uniform(1, 3))
    return None

def parse_page(html):
    soup = BeautifulSoup(html, "lxml")
    records = []
    for li in soup.select("li.book"):
        records.append({
            "title": li.select_one(".title").get_text(strip=True),
            "price": li.select_one(".price").get_text(strip=True),
        })
    return records

def save_csv(records, filename="books.csv"):
    with open(filename, "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=["title", "price"])
        writer.writeheader()
        writer.writerows(records)
    logging.info(f"已保存 {filename}")

def save_sqlite(records, filename="books.db"):
    conn = sqlite3.connect(filename)
    c = conn.cursor()
    c.execute("CREATE TABLE IF NOT EXISTS book (title TEXT, price TEXT)")
    c.executemany("INSERT INTO book VALUES (?, ?)",
                   [(r["title"], r["price"]) for r in records])
    conn.commit()
    conn.close()
    logging.info(f"已保存 {filename}")

def main():
    headers = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)..."}
    all_records = []
    for page in range(1, 4):
        url = f"https://books.example.com/list?page={page}"
        html = fetch_page(url, headers)
        if not html:
            continue
        records = parse_page(html)
        all_records.extend(records)
        logging.info(f"第 {page} 页抓到 {len(records)} 条")
        time.sleep(random.uniform(1, 3))
    save_csv(all_records)
    save_sqlite(all_records)
    logging.info(f"全部完成,共 {len(all_records)} 条")

if __name__ == "__main__":
    main()
```

模板的价值在于**结构**：每个函数职责单一，可单独拿一段 HTML 测 `parse_page`，测通了再联网。

## 六、异常处理、日志与数据校验

健壮爬虫的标配——异常让爬虫不因一个失败就崩掉，日志让问题可追溯：

```python
import logging, time, random
import requests
logging.basicConfig(filename="crawler.log", level=logging.INFO)
def fetch(url, headers, max_retries=3):
    """带重试的请求函数"""
    for attempt in range(max_retries):
        try:
            resp = requests.get(url, headers=headers, timeout=5)
            resp.raise_for_status()
            return resp.text
        except requests.exceptions.RequestException:
            wait = 2 ** attempt + random.uniform(0, 1)
            logging.warning(f"第 {attempt + 1} 次请求失败,等 {wait:.1f}s 重试")
            time.sleep(wait)
    logging.error(f"请求 {url} 重试 {max_retries} 次后仍然失败")
    return None
```

> **日志级别**：`DEBUG`（调试）、`INFO`（一般）、`WARNING`（警告）、`ERROR`（错误）。爬虫中用 `WARNING` 和 `ERROR` 就够。

抓取成功不等于数据可用，入库前过这几关：

| 检查项 | 含义 | 实现方式 |
| --- | --- | --- |
| 完整性 | 必填字段有没有缺失 | `if not all(r.values()): skip` |
| 唯一性 | 有无重复（翻页重复、重试重复） | 用 `set(title)` 去重 |
| 类型正确 | 价格是不是数字、评分是不是整数 | `float(str.replace("£",""))` |
| 范围合理 | 价格大于 0、评分在 1~5 | `assert 1 <= rating <= 5` |
| 一致性 | 字段格式统一（日期、货币单位） | 统一转 ISO 格式 |
| 数量校验 | 条数与页面显示是否吻合 | 对比分页元信息 |

```python
def validate(r):
    if not r["title"].strip(): return False
    try: r["price"] = float(str(r["price"]).replace("£", ""))
    except ValueError: return False
    return r["price"] > 0 and 1 <= int(r.get("rating", 0)) <= 5
```

> **中间检查点**：每抓完一页 `print` 条数、每存一次记录行数。别等 500 页全跑完才发现第 3 页开始就错了——**早失败早发现**。

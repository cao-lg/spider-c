前面所有解析都假设：数据已经写在 HTML 源码里。但很多网站用 JavaScript 动态生成内容——你「查看源代码」看不到数据，只有浏览器跑完 JS 后才出现。这类页面，`requests` 抓不到，得上**真实浏览器**。

> **为什么有些页面 requests 抓不到数据？** 因为这些页面把 HTML 作为「壳」，数据靠 JS 在浏览器里**实时渲染**。`requests` 只拿原始 HTML，不跑 JS，所以拿到的是空壳。

## 一、怎么判断页面是动态的

三种判断方法，优先级从高到低：

1. **右键 → 查看网页源代码** → 搜不到关键词 → 数据靠 JS 注入。
2. **F12 → Network** 里，真正的接口藏在 XHR/Fetch 中（这时**优先直接抓接口**，见第 9 章）。
3. 如果数据既不在源码、也没有独立接口，那就是纯前端渲染，必须上浏览器自动化。

> **判断口诀**：
> - 有接口（Network → XHR/Fetch）→ 优先抓接口（第 9 章）
> - 有源码（右键查看）→ 用 requests + BS4（第 4-6 章）
> - 都没？→ 上浏览器自动化（本章）

## 二、Playwright：把浏览器交给代码

Playwright 能启动一个真实（无头）浏览器，像人一样打开页面、等 JS 跑完、再读内容。

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)  # headless=True = 无头模式
    page = browser.new_page()
    page.goto("https://example.com/list", timeout=30000)
    page.wait_for_selector(".book")             # 等元素出现
    html = page.content()                        # 拿到渲染后的 HTML
    browser.close()
```

> Playwright 需要本地安装，**无法在浏览器运行器里执行**——请在电脑上跑。
>
> 安装命令：`pip install playwright`，然后 `playwright install` 下载浏览器内核。

### Playwright 流程图解

```
launch()        → 启动浏览器实例
new_page()      → 打开新标签页
goto()          → 导航到目标 URL
wait_for_selector() → 等待目标元素出现（等 JS 渲染）
content()       → 获取渲染后的完整 HTML
```

## 三、等待与交互

Playwright 提供丰富的等待和交互方法：

| 方法 | 含义 | 示例 |
| --- | --- | --- |
| `wait_for_selector` | 等元素出现 | `page.wait_for_selector(".book")` |
| `wait_for_timeout` | 硬等 N 毫秒（兜底） | `page.wait_for_timeout(1000)` |
| `click` | 点击按钮 | `page.click(".load-more")` |
| `fill` | 填写表单 | `page.fill("input[name='q']", "搜索词")` |
| `evaluate` | 执行 JS | `page.evaluate("document.title")` |

> **优先用 `wait_for_selector` 而不是 `wait_for_timeout`**。前者是条件等待（等元素出现就继续），后者是硬等固定时间（不管元素出来没都得等）。

## 五、什么时候才上 Playwright

| 场景 | 推荐方案 | 理由 |
| --- | --- | --- |
| 有 JSON 接口 | 第 9 章：`requests` + `resp.json()` | 最快、最稳定 |
| 数据在 HTML 源码 | requests + BS4 | 直接解析，无需浏览器 |
| 纯 JS 渲染，无接口 | Playwright | 必须，但重且慢 |

> **能不用 Playwright 就不用**。它比 `requests` 慢 10-100 倍，因为要启动完整浏览器。只有当你没有其他选择时才用它。

### 方案对比

| 方案 | 速度 | 稳定性 | 适用场景 |
| --- | --- | --- | --- |
| 抓接口（requests） | ⚡⚡⚡ 最快 | ⭐⭐⭐ 最稳 | 有 JSON API 的现代站 |
| 静态 HTML（BS4） | ⚡⚡ 快 | ⭐⭐ 好 | 老式静态页 |
| Playwright（浏览器） | 🐢 慢 | ⭐ 中等 | 纯 JS 渲染页 |

## 六、小结

- 判断动态：源码搜不到 + 无接口 → 需浏览器自动化。
- Playwright 流程：launch → goto → wait → content → BS4。
- 能用接口/静态就别用 Playwright，重且慢。
- 本地安装：`pip install playwright` + `playwright install`。

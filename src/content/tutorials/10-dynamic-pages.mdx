前面所有解析都假设:数据已经写在 HTML 源码里。但很多网站用 JavaScript 动态生成内容——你「查看源代码」看不到数据,只有浏览器跑完 JS 后才出现。这类页面,`requests` 抓不到,得上**真实浏览器**。

## 一、怎么判断页面是动态的

1. 浏览器里能看到数据,但 **右键 → 查看网页源代码** 搜不到关键词 → 数据靠 JS 注入。
2. F12 → Network 里,真正的接口藏在 XHR/Fetch 中(这时优先直接抓接口,见第 9 章)。
3. 如果数据既不在源码、也没有独立接口,那就是纯前端渲染,必须上浏览器自动化。

## 二、Playwright:把浏览器交给代码

Playwright 能启动一个真实(无头)浏览器,像人一样打开页面、等 JS 跑完、再读内容。

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://example.com/list", timeout=30000)
    page.wait_for_selector(".book")          # 等 JS 把 .book 渲染出来
    html = page.content()                     # 拿到「渲染后」的完整 HTML
    browser.close()

# 之后的解析和之前一样
from bs4 import BeautifulSoup
soup = BeautifulSoup(html, "lxml")
```

> Playwright 需要本地安装(`pip install playwright && playwright install`),且依赖系统浏览器,**无法在浏览器运行器里执行**——上面的代码请在你的电脑上跑。

## 三、等待与交互

动态页面最忌「数据还没出来就解析」。Playwright 提供多种等待:

```python
page.wait_for_selector(".list")              # 等某个元素出现
page.wait_for_timeout(1000)                  # 硬等 1 秒(兜底)
# 模拟点击「加载更多」
page.click(".load-more")
page.wait_for_load_state("networkidle")      # 等网络安静
```

## 五、什么时候才上 Playwright

- 能直接抓 JSON 接口 → 优先(第 9 章),最快最稳。
- 数据在 HTML 源码里 → `requests` + BS4 足矣。
- 只有 JS 渲染才有数据、又没接口 → 才用 Playwright。

无头浏览器重、慢、占资源,是「最后手段」,不是首选。

## 六、小结

- 判断动态:查看源代码搜不到数据、又没独立接口 → 需浏览器自动化。
- Playwright 流程:`launch` → `goto` → `wait_for_selector` → `content()` → 交给 BS4。
- 解析「渲染后的 HTML」和静态页一模一样;Playwright 只解决「拿到渲染后 HTML」这一步。
- 能用接口/静态解析就别用 Playwright,它重且慢。

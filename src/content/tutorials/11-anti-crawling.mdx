网站不希望被爬，于是设关卡。反爬不是攻防秀，而是**在合规前提下让请求像正常用户**。

> 反爬的本质：服务器识别出「你这个请求不像正常用户」。正常用户会怎么请求？随机 UA、间隔访问、带 Cookie。你的爬虫就要模拟这些行为。

## 一、常见反爬机制

| 机制 | 表现 | 应对 |
| --- | --- | --- |
| UA 检测 | 没 UA 直接 403 | 伪装浏览器 UA |
| 频率限制 | 太快返回 429 | time.sleep 控频 |
| 登录校验 | 需 Cookie 才给数据 | Session 带登录态 |
| 验证码 | 行为异常弹验证 | 降速模拟真人 |

### 反爬机制分层

| 层级 | 机制 | 难度 | 效果 |
| --- | --- | --- | --- |
| 第一层：基础 | UA 检测、请求头 | 低 | 挡新手爬虫 |
| 第二层：行为 | 频率限制、Cookie | 中 | 挡自动化脚本 |
| 第三层：高级 | 验证码、指纹识别 | 高 | 挡专业爬虫 |
| 第四层：法律 | robots.txt、合规 | N/A | 挡恶意爬虫 |

> 大多数网站止步第一、二层。你不需要学「高级反爬」，先把基础做好就超过 90% 的爬虫。

固定一个 UA 容易被识别。准备一组真实 UA，每次随机挑：

> **UA 轮换策略**：每请求换一个 UA，不要每页换——因为一个用户访问多页时 UA 是固定的，频繁变化反而可疑。

> **延时策略**：
> - 简单场景：`time.sleep(1)` 固定 1 秒
> - 进阶场景：`time.sleep(random.uniform(1, 3))` 随机 1-3 秒
> - 高级场景：用指数退避（指数退避策略见下文）

## 四、重试与指数退避

请求失败是常态。与其「一次失败就崩」，不如「失败就等一等再试」：

```python
import requests
import time
import random

def fetch(url, headers, max_retries=3):
    for attempt in range(max_retries):
        try:
            resp = requests.get(url, headers=headers, timeout=5)
            resp.raise_for_status()
            return resp.text
        except requests.exceptions.RequestException:
            wait = 2 ** attempt + random.uniform(0, 1)  # 指数退避
            print(f"第 {attempt + 1} 次失败,等 {wait:.1f}s 后重试")
            time.sleep(wait)
    return None  # 重试 3 次都失败,返回 None
```

> **指数退避**：第一次等 2s，第二次等 4s，第三次等 8s... 等太久会压垮服务器。这个策略平衡了「重试」和「礼貌」。

## 五、代理原理(进阶)

代理让你换个 IP 地址访问目标网站：

```python
proxies = {"http": "http://1.2.3.4:8080"}
resp = requests.get(url, proxies=proxies, timeout=5)
```

> **代理来源务必合规**。免费代理常不稳定且有安全风险（代理服务器可以读取你的请求数据）。

### 代理类型

| 类型 | 成本 | 稳定性 | 推荐场景 |
| --- | --- | --- | --- |
| 免费代理 | 免费 | 差 | 不推荐（学习除外） |
| 付费代理 | 低-中 | 中-好 | 中小规模爬虫 |
| 住宅代理 | 高 | 好 | 高隐蔽需求 |
| 自建代理 | 零（需多服务器） | 好 | 大规模 |

## 六、常见反爬应对清单

| 反爬措施 | 症状 | 排查思路 |
| --- | --- | --- |
| 403 状态码 | 无 UA 直接拒绝 | 加 `User-Agent` 请求头 |
| 429 状态码 | 请求太快 | 加 `time.sleep` 降速 |
| 空页面 | 页面 HTML 存在但无数据 | 检查是否需登录（Cookie） |
| 验证码弹窗 | 行为异常触发验证码 | 降速、模拟真人行为 |
| IP 被封 | 连续请求都失败 | 检查请求频率、考虑代理 |

## 七、小结

- 反爬四板斧：伪装 UA、带请求头、控频、必要时代理。
- 随机 UA + 随机延时比固定更安全。
- 重试配合退避策略，别死循环。
- 永远先问自己：「这个请求像正常用户吗？」
- 合规优先，别碰红线。

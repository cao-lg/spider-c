上一章把 HTTP 讲清楚了，这一章用 `requests` 把它变成代码。`requests` 是 Python 里最流行的 HTTP 库，把「发请求」从十几行收成了两三行。它把上一章讲的请求三要素（方法+URL、请求头、请求体）和响应结构（状态码+响应头+响应体）都封装成了简洁的 API。

> **为什么要用 requests 而不是 urllib？** urllib 是 Python 标准库，功能完整但 API 繁琐——拼接 URL、处理编码、管理 Cookie 都要手动写。`requests` 是第三方库，API 优雅、参数化清晰，一行 `requests.get(url)` 搞定一切。虽然它多了一个安装步骤（第 1 章已解决），但它是爬虫事实上的标准。

> **本章代码分两类**：标注「本地运行」的用 `httpbin.org` / 课程靶站实测案例，请在你自己电脑的 Python 里跑；页面底部的「代码实战」运行器（Pyodide）已对课程靶站 `SITE_BASE` 打好补丁，里面用靶站的练习可以直接跑，但**不要在练习里请求公网**（会被 CORS 拦截，原因见第 1 章第七节）。

## 一、第一个 GET 请求与 Response 对象

```python
import requests

resp = requests.get("https://books.example.com/list")
print(resp.status_code)   # 200
print(resp.url)           # 实际访问的地址(含重定向后的)
print(len(resp.text))     # 网页 HTML 文本长度
```

`resp`（Response 对象）是你最该熟悉的东西——它正是上一章「响应三要素」在代码里的化身：

| 属性 | 含义 | 对应 HTTP | 何时用 |
| --- | --- | --- | --- |
| `resp.status_code` | 状态码(200/403/404...) | 状态行 | 判断请求成功还是失败 |
| `resp.text` | 解码后的网页文本(字符串) | 响应体 | 解析 HTML / JSON 文本 |
| `resp.content` | 原始字节(下载图片/文件用) | 响应体 | 二进制内容（图片、PDF） |
| `resp.headers` | 响应头字典 | 响应头 | 检查编码、内容类型 |
| `resp.url` | 最终 URL(跟随重定向后) | — | 确认是否被重定向 |
| `resp.history` | 重定向经过的响应列表 | — | 追踪 301/302 跳转链 |
| `resp.encoding` | 编码,乱码时手动设 `resp.encoding = "utf-8"` | — | 中文乱码时强制指定编码 |

> **`resp.text` vs `resp.content` 怎么选？** 看你要什么：要**字符串**用 `.text`（直接 `.get_text()` 或 `.json()`），要**原始字节**用 `.content`（下载图片、文件、音频等二进制文件）。它们的关系是 `resp.text == resp.content.decode(resp.encoding)`——乱码问题就出在这个 decode 用了错误的编码。

## 二、真实案例：用 httpbin.org 验证四种请求写法

下面四段请在**本地 Python** 跑，`httpbin.org` 会把你的请求原样回显，验证参数到底传对了没有。

### 2.1 GET + params

```python
import requests
r = requests.get("https://httpbin.org/get", params={"q": "python", "page": 2}, timeout=10)
print(r.json()["args"])   # {'q': 'python', 'page': '2'} —— 参数原样回显
print(r.url)              # https://httpbin.org/get?q=python&page=2
```

### 2.2 POST + data（传统表单）

```python
r = requests.post("https://httpbin.org/post", data={"user": "u", "pwd": "p"}, timeout=10)
data = r.json()
print(data["form"])                    # {'user': 'u', 'pwd': 'p'}
print(data["headers"]["Content-Type"]) # application/x-www-form-urlencoded
```

### 2.3 POST + json（现代 API）

```python
r = requests.post("https://httpbin.org/post", json={"key": "value"}, timeout=10)
data = r.json()
print(data["json"])                    # {'key': 'value'}
print(data["headers"]["Content-Type"]) # application/json —— requests 自动设置
```

### 2.4 自定义 headers

```python
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Accept-Language": "zh-CN,zh;q=0.9",
}
r = requests.get("https://httpbin.org/headers", headers=headers, timeout=10)
print(r.json()["headers"]["User-Agent"])  # 已是浏览器样式，不再是 python-requests
```

> 这四段代码覆盖了 requests 最核心的四种「填参数」方式。我实测 `httpbin.org` 均正常回显——建议你亲手跑一遍，对着回显结果理解每种参数去了哪里。

## 三、查询参数：用 params 代替手拼 URL

别手写 `?q=python&page=2`，交给 `params` 字典，`requests` 会自动编码：

```python
resp = requests.get(
    "https://books.example.com/search",
    params={"q": "python", "page": 2},
)
print(resp.url)  # https://books.example.com/search?q=python&page=2
```

## 四、请求头与 UA 伪装

很多站点看到「没有 User-Agent 的请求」就直接 403。`requests` 默认 UA 是 `python-requests/x.x`，很容易露馅。

> **User-Agent 的潜规则**：`User-Agent` 是服务器用来「识别客户端身份」的标识。浏览器发的 UA 通常包含操作系统、浏览器引擎、版本号。爬虫默认 UA 是 `python-requests`，一看就知道不是浏览器。把浏览器 F12 → Network 里看到的真实 `User-Agent` 抄过来，是最快的方式（第 2 章实验二已演示如何用 httpbin 观察）。

```python
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "Accept-Language": "zh-CN,zh;q=0.9",
}
resp = requests.get("https://books.example.com/list", headers=headers)
```

### 常用请求头一览

| 请求头 | 值示例 | 作用 |
| --- | --- | --- |
| `User-Agent` | `Mozilla/5.0 (Windows NT 10.0; Win64; x64)...` | 告诉服务器「我是谁」 |
| `Accept` | `text/html,application/json,*/*;q=0.9` | 告诉服务器「我想要什么格式」 |
| `Accept-Language` | `zh-CN,zh;q=0.9` | 想要的语言 |
| `Referer` | `https://books.example.com/list` | 从哪个页面来的 |
| `Cookie` | `session_id=abc123...` | 登录态 / 会话标识 |

> 生产环境建议**维持一个真实 UA 不要乱变**（真人浏览时 UA 在一整个会话里是稳定的，频繁跳变反而像机器人）。第 11 章会讲到更完整的请求头策略。

## 五、POST 请求：data 与 json 怎么选

登录、搜索表单多用 POST，参数放在请求体里。`data` 和 `json` 的选择取决于服务端要什么格式：

```python
# 表单格式（application/x-www-form-urlencoded）
resp = requests.post(url, data={"username": "u", "password": "p"})

# JSON 格式（application/json，接口最常见）
resp = requests.post(url, json={"key": "value"})
```

### params / data / json 三者对比

| 参数 | 放在哪 | Content-Type | httpbin 回显字段 | 典型用途 |
| --- | --- | --- | --- | --- |
| `params=` | URL 查询串 | 无（在 URL 上） | `args` | GET 传参、分页、筛选 |
| `data=` | 请求体（表单） | `application/x-www-form-urlencoded` | `form` | 传统网页表单、登录 |
| `json=` | 请求体（JSON） | `application/json`（自动设置） | `json` | 现代 Web API、前后端分离接口 |

> **判断用哪个的方法**：打开浏览器 F12 → Network → 点那条 POST 请求 → Payload（或 Form Data）标签。看到 `key=value` 形式就用 `data=`，看到 JSON 结构（花括号）就用 `json=`。选错格式，服务器会「假装收不到」参数。

## 七、Session：保持登录态与连接复用

每次 `requests.get()` 都是「新会话」，不带 Cookie。要维持登录，用 `Session`，它会自动保存并带上 Cookie：

```python
s = requests.Session()
s.post(login_url, data={"user": "u", "pwd": "p"})  # 登录,拿到 Cookie
resp = s.get(protected_url)                         # 同一会话,自动带 Cookie
```

> **Session 不只是登录**：它还会保持连接池（复用 TCP 连接，提升性能）、自动管理 Cookie jar。如果你的爬虫需要**反复访问同一个域名**，用 Session 比裸调 `requests.get()` 更高效。

### 什么时候用 Session

| 维度 | 裸 `requests.get()` | `requests.Session()` |
| --- | --- | --- |
| Cookie | 每次请求都不带 | 自动保存并带上 |
| TCP 连接 | 每次新建连接 | 连接池复用，少握手 |
| 多次请求同域名 | 较慢 | 更快 |
| 需要登录的页面 | 做不到 | 轻松维持登录态 |
| 适用场景 | 单次、简单的请求 | 多页抓取、需登录、会话保持 |

> **实践建议**：写爬虫时默认就 `s = requests.Session()`，全程用 `s.get()` / `s.post()`，几乎没有坏处——既省连接开销，又为将来可能的登录需求留好口子。

## 八、超时、raise_for_status 与异常处理

### 8.1 超时：永远给请求加 timeout

不设超时，网站卡住时你的脚本会**永远挂起**。设超时是健壮爬虫的第一条铁律：

```python
requests.get(url, timeout=5)             # 连接和读取都最多 5 秒
requests.get(url, timeout=(3, 10))       # 连接 3 秒、读取 10 秒（更精细）
```

| 写法 | 含义 | 建议 |
| --- | --- | --- |
| `timeout=5` | 连接与读取共用 5 秒上限 | 简单场景够用 |
| `timeout=(3, 10)` | 连接超时 3 秒、读取超时 10 秒 | ⭐ 推荐，区分「连不上」与「服务器慢」 |
| 不设 timeout | 无限等待 | ❌ 禁止，脚本会挂死 |

> **超时时间设多少合适？** 连接超时 3-5 秒（正常网络连上很快，连不上就是真连不上）；读取超时 10-30 秒（慢接口留余量）。别设成 120 秒——那不叫健壮，那叫把故障无限拖长。

### 8.2 raise_for_status：让错误显式化

```python
resp = requests.get(url, timeout=10)
resp.raise_for_status()   # 状态码是 4xx/5xx 时主动抛 HTTPError
```

| 写法 | 行为 | 适用场景 |
| --- | --- | --- |
| `if resp.status_code != 200: ...` | 手动判断，能区分具体码 | 需要针对不同状态码做不同处理 |
| `resp.raise_for_status()` | 4xx/5xx 统一抛 `HTTPError` | ⭐ 通用场景，配合 try/except 简洁 |

### 8.3 完整异常处理

```python
try:
    resp = requests.get(url, timeout=5)
    resp.raise_for_status()
except requests.exceptions.Timeout:
    print("超时,稍后重试")
except requests.exceptions.HTTPError:
    print("HTTP 错误:", resp.status_code)
except requests.exceptions.RequestException as e:
    print("请求失败:", e)
```

`raise_for_status()` 把「静默的 4xx/5xx」变成异常，配合 `try/except` 才能写出健壮爬虫——**不让一个失败请求搞掉整条流水线**。

### 常见异常一览

| 异常类 | 触发条件 | 应对 |
| --- | --- | --- |
| `requests.exceptions.Timeout` | 超过 timeout 秒无响应 | 加 sleep 重试 |
| `requests.exceptions.HTTPError` | `raise_for_status()` 发现非 2xx | 检查状态码，判断是否需要重试 |
| `requests.exceptions.ConnectionError` | 网络断开、DNS 解析失败 | 检查网络，稍后重试 |
| `requests.exceptions.TooManyRedirects` | 重定向超过 10 次 | URL 有循环重定向，放弃或手动处理 |
| `requests.exceptions.SSLError` | 证书校验失败 | 见第十节常见坑 |

> **为什么 `r.encoding = "utf-8"` 能解决乱码？** 服务器有时没在响应头里正确声明编码，requests 会按默认规则（常是 ISO-8859-1）去 decode 字节，中文就变成 `æ\x85` 之类的乱码。手动指定 utf-8 后，`r.text` 会用正确编码重新解码。也可以用 `r.apparent_encoding` 让 requests 猜，但显式指定更可靠。

## 十一、常见坑排查表

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| 脚本卡住不动、永远没响应 | 没设 timeout | 一律加 `timeout=(3, 10)`，杜绝无限等待 |
| 设了 timeout 仍频繁超时 | 超时时间太短或目标太慢 | 适当调大读取超时到 10-30 秒，配合重试 |
| 中文乱码（如 `æ\x85...`） | 服务器编码声明错误，requests 猜错 | `r.encoding = "utf-8"` 或 `r.content.decode("utf-8")` |
| `SSLError: certificate verify failed` | 证书过期、自签名或系统缺 CA | 优先更新 certifi；临时可 `verify=False`（有中间人风险，仅调试用） |
| 走了代理后请求失败 | 代理配置错误或代理不可用 | 检查 `proxies` 字典 / 环境变量 `HTTP_PROXY`、`HTTPS_PROXY` |

## 十二、小结

- `requests.get()` / `requests.post()` 发请求；响应对象 `resp` 的 `status_code` / `text` / `content` / `headers` / `url` 对应 HTTP 响应各要素。
- 参数三兄弟：`params=` 进 URL（GET）、`data=` 进表单、`json=` 进 JSON 体（现代 API）；别手拼 URL，交给 params 自动编码。
- 请求头用 `headers=` 伪装 UA；反复访问同域名用 `Session()` 复用连接与 Cookie。
- **联网必加 `timeout=(3, 10)`**，用 `raise_for_status()` + `try/except` 让错误显式化，不让单个失败搞挂整条流水线。
- 中文乱码用 `r.encoding = "utf-8"` 修正，二进制用 `.content`。
- 练习数据只来自内置模拟数据或课程靶站 `SITE_BASE`；公网案例请在本地跑。

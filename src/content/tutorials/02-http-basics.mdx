爬虫本质上是**模拟浏览器发 HTTP 请求、读懂服务器返回的响应**。不懂 HTTP，你只会「抄代码」，一旦网站变卦就束手无策。这一章把 HTTP 讲透。

> 你可以把 HTTP 想象成「你和服务器之间的对话规则」。浏览器和服务器之间说的每一句话，都遵循 HTTP 协议。爬虫就是「旁听」这些对话，然后自己也开口说话。

## 一、请求 / 响应模型

一次抓取就是一次对话：

```
你(客户端)  --请求 Request-->   服务器
你(客户端)  <--响应 Response--   服务器
```

请求里包含：要什么（URL）、用什么动作（方法）、附带什么信息（请求头/请求体）。
响应里包含：状态码（成不成功）、响应头（元信息）、以及真正的网页内容（HTML/JSON/图片）。

| 阶段 | 方向 | 你带什么 | 服务器回什么 |
| --- | --- | --- | --- |
| **请求 Request** | 客户端 → 服务器 | URL、方法、请求头、请求体 | — |
| **响应 Response** | 服务器 → 客户端 | — | 状态码、响应头、网页内容 |

> 理解了这个「双向对话」模型，你读任何 HTTP 相关的报错（比如 403、429、timeout），都知道问题出在哪一边。

## 二、URL 结构拆解

URL 是爬虫的「目标地址」。一个完整的 URL：

```
https://books.example.com/search?q=python&page=2#top
|_____|   |__________________|  |____________|  |___|
  scheme     host + path          query         fragment
```

| 部分 | 含义 | 示例 |
| --- | --- | --- |
| `https` | 协议(scheme) | `http`（不安全）/ `https`（加密） |
| `books.example.com` | 主机(host) | 域名或 IP 地址 |
| `/search` | 路径(path) | 服务器上的资源路径 |
| `?q=python&page=2` | 查询参数(query) | `&` 分隔多个，`=` 键值对 |
| `#top` | 片段(fragment) | 浏览器内锚点，**不会发给服务器** |

> **注意**：`#` 后面的 fragment 只存在于浏览器本地（比如跳到页面某个锚点），服务器永远不会收到它。这也是为什么 URL 里改 `#` 后面的值不影响请求。

## 三、常用方法与状态码

### 3.1 方法（HTTP Verb）——你要服务器做什么

| 方法 | 含义 | 爬虫中何时用 |
| --- | --- | --- |
| `GET` | 取数据（参数在 URL 里） | 最常见，抓列表页、详情页 |
| `POST` | 提交数据（参数在请求体里） | 登录、搜索表单、提交筛选条件 |
| `PUT / DELETE` | 修改/删除资源 | 爬虫极少直接使用 |

> **GET 和 POST 的核心区别**：GET 的参数拼在 URL 里（可见、有长度限制、可缓存），POST 的参数放在请求体里（不可见、无长度限制、不可缓存）。大多数爬虫以 GET 为主，少数场景（如登录、搜索）需要 POST。

### 3.2 状态码（Status Code）——服务器说结果

状态码是服务器对请求的「一句话回应」，由三位数字组成：

| 范围 | 含义 | 常见码 | 爬虫怎么处理 |
| --- | --- | --- | --- |
| `2xx` | 成功 | 200 OK | 正常解析 |
| `3xx` | 重定向 | 301 永久/302 临时 | requests 默认自动跟随，注意最终 URL |
| `4xx` | 客户端错误 | 403 禁止 / 404 不存在 / 429 太频繁 | 检查请求头、降速、换 IP |
| `5xx` | 服务器错误 | 500 内部 / 503 维护 | 重试或稍后再来 |

> 看到 **403** 别慌——通常是**请求头太「裸」**（没有 User-Agent），服务器当机器人拦了。下一章学 `requests` 时我们就用请求头来解决它。
>
> 看到 **429**（Too Many Requests）= 你爬太快了，服务器限流。加 `time.sleep` 降速即可。

## 四、请求头：你给服务器的「自我介绍」

请求头是一组键值对，告诉服务器「我是谁、我要什么格式」。爬虫最关心的几个：

| 请求头 | 作用 | 爬虫关注点 |
| --- | --- | --- |
| `User-Agent` | 浏览器标识 | 很多站点只认正常 UA，缺失就 403 |
| `Cookie` | 登录态 / 会话标识 | 需要登录才能看的内容靠它 |
| `Referer` | 从哪个页面来的 | 部分防盗链站点会校验 Referer |
| `Accept-Language` | 想要的语言 | 影响返回内容语种 |
| `Accept` | 期望的内容类型 | 如 `application/json` 或 `text/html` |

> **如何找真实的请求头**？打开浏览器 F12 → Network → 点任意请求 → Headers → Request Headers，就能看到浏览器实际发的请求头。照着抄是最快的学习方式。

## 五、常见状态码排查流程

```
收到状态码 → 对照表格 → 判断原因
    → 403 → 加 User-Agent 重试
    → 429 → 加 time.sleep 降速
    → 404 → 检查 URL 是否正确
    → 503 → 等几秒后重试
```

## 六、小结

- HTTP = 请求 → 响应。请求带 URL/方法/头/体，响应带回状态码/头/内容。
- URL 五段：协议 / 主机 / 路径 / 查询 / 片段（`#` 不发服务器）。
- `GET` 取、`POST` 交；状态码 `2xx` 成功、`4xx` 多是被拦、`5xx` 可重试。
- 请求头里 `User-Agent` / `Cookie` / `Referer` 是爬虫最常调的三个。
- 下一章用 `requests` 把这些概念变成代码。

本页底部「代码实战」会让你用 `requests` 实际发一次请求，感受一下从理论到实践的那一跳。

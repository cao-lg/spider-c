写爬虫第一步不是写代码，而是把**运行环境**收拾干净。环境乱了，后面十倍的坑都出在「我本地能跑，你那怎么不行」。这一章把地基打牢。

> 这一章的内容，你将来 every 项目都会遇到。**环境管理**是区分「写了一段脚本」和「做一个正经项目」的分水岭。

## 一、为什么需要隔离环境

你以后会同时做很多 Python 项目，每个项目依赖的库版本可能冲突。比如：

- 项目 A 需要 `requests 2.x`（老库，只兼容旧版）
- 项目 B 需要 `requests 2.32+`（新版有 bugfix）

如果都装在全局 Python 里，`import requests` 永远只指向一个版本，你要么 A 跑不了，要么 B 跑不了。**虚拟环境(venv)**就是给每个项目单独建一个小房间，互不干扰。

| 方案 | 适用场景 | 缺点 |
| --- | --- | --- |
| 全局安装 | 快速实验，临时用 | 库版本冲突，无法共存 |
| venv 虚拟环境 | 单个项目（推荐） | 需手动激活 |
| conda | 数据科学（需多版本 Python） | 体积大，启动慢 |
| 浏览器运行器 | 本教程练习，即开即用 | 无法装任意库，受限环境 |

> **本教程的浏览器运行器**已经预装好了 `requests` / `BeautifulSoup` / `lxml`，你不用装也能直接在页面里跑示例。但学会本地环境管理，是你把爬虫跑在自己电脑上的前提。

## 二、安装并验证 Python

1. 到 [python.org](https://www.python.org/downloads/) 下载 **Python 3.10+**（安装时**务必勾选** "Add Python to PATH"）。
2. 打开终端验证：

```bash
python --version      # 或 python3 --version
# 期望看到: Python 3.10.x 或更高
```

如果提示「找不到命令」，大概率是安装时没勾 PATH，或需要用 `python3`（Linux/macOS 常见）。

### 常见安装问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `command not found: python` | 没装或没加 PATH | 重新安装，勾 PATH |
| `command not found: python3` | 需要 `python3` 前缀 | 用 `python3 --version` |
| `pip: command not found` | 没装 pip | 运行 `python -m ensurepip --upgrade` |
| 多个 Python 版本 | 系统自带 Python 和你装的不一样 | 用 `which python` / `where python` 确认路径 |

> **Windows 特别注意**：如果你同时装了 Anaconda，`python` 可能指向 conda 而非你刚装的 Python。建议用 `python3` 或完整路径区分。

## 三、用 venv 创建虚拟环境

在项目目录里：

```bash
# 在当前目录创建名为 .venv 的虚拟环境
python -m venv .venv

# 激活(Windows)
.venv\Scripts\activate
# 激活(macOS / Linux)
source .venv/bin/activate
```

激活后，终端提示符前面会出现 `(.venv)`，表示你已进入这个隔离房间。之后用 `pip` 装的库都只装在这里。

> `.venv` 是社区约定俗成的虚拟环境目录名（前面加点表示隐藏，不会干扰项目文件）。你可以改名，但 `.venv` 是最被广泛认知的。

## 四、用 pip 安装核心库

爬虫三件套：

```bash
pip install requests beautifulsoup4 lxml
```

- **requests**：发 HTTP 请求拿网页（最流行的 HTTP 库）
- **beautifulsoup4**：把 HTML 解析成好用的对象（配 `lxml` 解析器最快）
- **lxml**：高性能解析引擎，XPath 也靠它

升级 pip 本身（可选）：`python -m pip install --upgrade pip`。

### 验证安装成功

```bash
pip list | grep -i "requests\|beautifulsoup\|lxml"
# 或
pip show requests beautifulsoup4 lxml
```

## 六、pip 常用操作速查

| 操作 | 命令 |
| --- | --- |
| 安装一个库 | `pip install 包名` |
| 卸载一个库 | `pip uninstall 包名` |
| 列出已装 | `pip list` |
| 查包详情 | `pip show 包名` |
| 升级 pip | `python -m pip install --upgrade pip` |
| 导出依赖 | `pip freeze > requirements.txt` |
| 从文件装 | `pip install -r requirements.txt` |

> `requirements.txt` 是 Python 项目的「环境清单」——把它交给同事，对方一行命令就能装齐所有依赖。

## 七、常见坑与排查

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `pip install` 成功但 `import` 失败 | 没激活 venv，或激活错了环境 | 用 `which pip` (Linux) 或 `where pip` (Windows) 确认路径指向 `.venv` |
| Windows 激活报权限错误 | PowerShell 执行策略限制 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `pip` 和 `python` 不是一对 | 全局 pip 装了，venv 没装 | 激活 venv 后运行 `python -m pip install 包名`（推荐写法） |
| 装完库却 `ImportError` | 用了另一个 Python 解释器 | 确保 `python` 和 `pip` 来自同一个环境（用 `python -m pip` 最稳妥） |

## 八、小结

- 先装 Python 3.10+，验证 `python --version`。
- 每个项目用 `python -m venv .venv` 隔离，装库前先激活。
- 爬虫三件套：`requests`（请求）+ `beautifulsoup4`（解析）+ `lxml`（引擎/XPath）。
- 装完用 `import` 验证，比「以为装好了」可靠。
- `requirements.txt` 是环境清单，一行 `pip install -r requirements.txt` 就能恢复所有依赖。
